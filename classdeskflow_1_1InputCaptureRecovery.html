Detailed Description

Decides when a Wayland input-capture grab may be released and when pointer barriers may be replaced.

Mutter rejects SetPointerBarriers while a capture is activated, and it rejects ReleaseAt when the cursor point is outside a zone. Either failure leaves the EIS client holding buttons, so local clicks never reach applications. This state machine keeps the grab marked held until the portal reports deactivation, refuses barrier updates until then, and sends a plain Release so a bad cursor point cannot leave the grab up.

bool deskflow::InputCaptureRecovery::noteStoppedEmulating ( )

EIS stop_emulating. The stop event has no sequence, so this counts down the devices started for the current grab. Returns true only when the portal has also deactivated and the last current device has stopped. A stop on its own does not end the grab: the stops after a barrier bounce belong to the activation we already left.

◆ requestRelease()

ReleaseRequest deskflow::InputCaptureRecovery::requestRelease ( bool positionIsInsideZone)
inline

Ask the portal to give the pointer back.

A second call for the same activation does nothing. A new activation (the pointer bounced off a barrier and the compositor grabbed again) is a different grab and must be released on its own. The portal spec ignores Release for an id that is no longer current, so suppressing that second call leaves the new grab held.
